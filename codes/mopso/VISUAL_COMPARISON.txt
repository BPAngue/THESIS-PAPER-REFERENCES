══════════════════════════════════════════════════════════════════════════
                         OLD APPROACH (Current)
══════════════════════════════════════════════════════════════════════════

Architecture:
┌──────────────────────────────────────────────────────────────────┐
│  Single "Voted_GBest" (One best solution for entire system)     │
└──────────────────────────────────────────────────────────────────┘
                                │
        ┌───────────────────────┼───────────────────────┐
        │                       │                       │
    ┌───▼────┐            ┌────▼─────┐          ┌─────▼────┐
    │Thread 1│            │Thread 2  │          │Thread 3  │
    │ PSO-GWO│◄──────────►│ PSO-GWO  │◄────────►│ PSO-GWO  │
    │        │            │          │          │          │
    │Alpha   │  Ring     │Alpha     │  Ring    │Alpha     │
    │Beta    │  Topology  │Beta      │  Topology│Beta      │
    │Delta   │            │Delta     │          │Delta     │
    └────────┘            └──────────┘          └──────────┘

Fitness Function:
┌──────────────────────────────────────────────────────────────────┐
│  IF perfect: fitness = correctness + 0.1 * unused_gates         │
│  ELSE:       fitness = correctness                               │
└──────────────────────────────────────────────────────────────────┘

Problems:
✗ Conflicting objectives (correctness vs simplicity)
✗ Forced replacement every iteration → premature convergence
✗ Random "earthquake" destroys good partial solutions
✗ Only keeps ONE best solution
✗ Ring topology shares exact copies → similar solutions in all threads

Performance on Full-Adder (3 inputs, 2 outputs):
────────────────────────────────────────────────────────────────────
Correctness: ~87.5% (14/16 correct outputs)
Success Rate: Low on complex circuits
Convergence: Stagnates frequently


══════════════════════════════════════════════════════════════════════════
                         NEW APPROACH (Proposed)
══════════════════════════════════════════════════════════════════════════

Architecture:
┌─────────────────────────────────────────────────────────────────────┐
│         Global Pareto Archive (200 diverse solutions)               │
│  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐                 │
│  │16/16 │  │16/16 │  │15/16 │  │14/16 │  │13/16 │  ...            │
│  │8 gate│  │9 gate│  │6 gate│  │7 gate│  │5 gate│                 │
│  └──────┘  └──────┘  └──────┘  └──────┘  └──────┘                 │
│  Perfect   Perfect   Simple    Balanced  Minimal                    │
└─────────────────────────────────────────────────────────────────────┘
                                │
        ┌───────────────────────┼───────────────────────┐
        │                       │                       │
    ┌───▼────┐            ┌────▼─────┐          ┌─────▼────┐
    │Thread 1│            │Thread 2  │          │Thread 3  │
    │ MOPSO  │◄──────────►│ MOPSO    │◄────────►│ MOPSO    │
    │        │            │          │          │          │
    │Local   │  Selective │Local     │  Selective│Local    │
    │Archive │  Migration │Archive   │  Migration│Archive  │
    │(100)   │            │(100)     │          │(100)     │
    └────────┘            └──────────┘          └──────────┘

Two Objectives (NOT combined):
┌──────────────────────────────────────────────────────────────────┐
│  Objective 1: Maximize correctness (# correct outputs)          │
│  Objective 2: Minimize complexity (# active gates)              │
│                                                                  │
│  Solution A dominates B if:                                     │
│    - A is better in at least one objective AND                  │
│    - A is not worse in any objective                            │
└──────────────────────────────────────────────────────────────────┘

Innovations:
✓ Pareto archive maintains diverse solutions
✓ Selective migration (top 3 diverse solutions)
✓ Adaptive diversity injection based on progress
✓ Crowding distance for diversity maintenance
✓ Grid-based leader selection (less crowded regions)
✓ Adaptive mutation (strong early, gentle late)
✓ Progress-aware strategies

Expected Performance on Full-Adder:
────────────────────────────────────────────────────────────────────
Correctness: 95-100% (15-16/16 correct outputs)
Success Rate: High on complex circuits
Convergence: Better exploration, less stagnation

                         ADAPTIVE STRATEGY

The system adapts based on current progress:

                        │                 │ Small adjustments to best
                        │                 │
